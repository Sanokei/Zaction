## Observed boundary and refinement

Spec §3.4 requires usable open discussion and public corrections; §§4.5/9 require honest offline participation and foreground recovery. The actual accepted comment remains identical in the private composer, with Post comment enabled. Current `publishContribution` trims/enqueues text; receipt acceptance retains the draft, and its React cache can mask durable state. Posting has no atomic duplicate guard for the exact contribution tuple.

Acknowledgement will use the original local operation and receipt: exact room, profile, action, normalized root/reply parent, submitted text and operation ID. An accepted receipt must also match the same-ID accepted contribution, never another post merely containing identical words. Server receipt time, not arrival order, determines newer outcomes; rejected or unconfirmed work stays reviewable. No receipt arrival automatically clears an editor.

One causal detail is necessary: after deliberately starting another comment, typing identical words must not be mistaken for the earlier accepted draft after reload. Add only an optional **private `composerReset: true` marker on the existing local receipt wrapper**. This is an explicit local shape extension, not a new ledger, collection, schema version, server receipt/operation field, migration or synthetic history. Missing markers remain missing. Keep original operation, receipt ID/reason/time/acceptance and posted comment unchanged. Mark matching handled receipt identities only during successful deliberate reset; preserve those private markers on stable replay, and never trust a marker supplied by a remote response.

## Bounded implementation

1. Derive ready, pending, posted, rejected and unconfirmed status from exact existing records. Pending/posted matching blocks accidental repeated posting, while different text/parent remains editable. Add the same duplicate check inside the atomic IndexedDB enqueue so rapid/cross-tab clicks cannot create two matching in-flight requests.
2. Keep pending text editable so newer typing is retained. Retain exact posted text with visible Posted status and an explicit Start another comment control. Keep source facts, group decisions and private progress separate from this local acknowledgement.
3. Start another compares fresh room/member/action/parent, exact RAW durable draft (including whitespace), exact accepted operation/receipt and accepted contribution, with no matching pending request. Only a committed match clears that discussion field and its matching reply target and marks existing matching handled receipts. Minutes, other plans, original receipts and newer text remain unchanged. Return changed/unavailable/failed rather than claim success on conflict or quota failure.
4. Guard UI cache clearing/focus by captured editor version, raw value and room/member/action/parent after the durable reset succeeds. A keystroke or reply change during the reset wins. Focus follows committed DOM; polling and late receipts do not move it.
5. Preserve reset markers when the same original receipt/operation is replayed. Rejection history retains the original text. Comment rejection must not refill an intentionally cleared or newer editor; recovery remains explicit. If the original reply target is unavailable, preserve its draft and show an explicit recovery choice rather than silently posting to root.

## Implemented and locally verified

The exact-record selector and reset helper are implemented in `src/comments.ts`. Pending is scoped to the original room/profile/action/parent/text; Posted additionally needs the same-ID accepted contribution. Unconfirmed accepted receipts block repeats and offer refresh. Newer rejections are selected by original server time rather than replay arrival order. Existing server receipt fields and operations are retained verbatim; the only causal addition is the optional private reset marker already described above.

Contribution enqueue now rechecks the raw durable draft, reply target and namespace inside the same IndexedDB transaction as duplicate detection. Save and reply actions capture their namespace. Start another performs the exact receipt/draft compare-and-set, clears only that discussion and matching reply target, and marks existing matching handled receipt wrappers. It never runs on receipt arrival. Replay strips remote markers and retains a private marker only for the same immutable receipt and original operation. Rejected comment text stays in explicit history recovery and cannot refill a deliberately cleared editor. Older-room recovery cannot write into a new room merely because an action ID matches.

UI caches and versions are scoped by room/profile/action/field. Confirmed-saved pristine caches adopt a newer durable reset/value; dirty/newer text and local reply intent remain. Post preflight repeats that guard so a stale tab cannot flush the old submitted body back into storage. Successful reset clears only an unchanged matching cache field; a later edit is retained/resaved. Focus waits for a matching committed empty root editor and does not steal focus from another control, onboarding or a native modal. A missing original reply target is displayed with its retained draft and an explicit recovery choice, never silently redirected.
