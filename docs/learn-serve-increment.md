## Problem and source selection

Spec §§3.1–3.2 (printed p.7) connects sourced civic information to concrete service, with personal applications left to the responsible organization. §8 (pp.20–21) requires identifiable public sources/dates and official deep links instead of inferred personal voter information. Phase 1, §9 (pp.22–23), includes Learn, cached public information, deliberation and published minutes. Equal voice remains independent of reading, volunteering and self-reported progress.

Current Learn contains three generic outbound cards. It has no local opportunity with a checked source date/jurisdiction, no distinction between a saved source summary and a live official page, and no return into an authored question with that exact reference preserved. Existing plan `sourceLabel`/`sourceUrl` are editable member assertions; they cannot establish that the author is the source organization or that its guidance is current.

## Bounded implementation plan

1. Put this one source card in existing Learn. Make the existing Learn & serve entry reachable at the point of need on narrow screens, without another navigation tab or resource library. Show publisher, jurisdiction, exact reviewed snapshot/date, a manual next-step checklist and source links. The guide is organizational, not governmental; community assertions never inherit its authority.
2. Bundle an append-only curated source catalog shared by client/server. A reference is the exact `{opportunityId, snapshotId}` pair; metadata includes the checked source URL/commit/body hash and successful review time. Page opening, reconnect, app sync and official-link clicks cannot advance that date. This is a saved summary/source reference, not an offline copy of the official website or a live checking service.
3. Use “dated source note,” “older source note” on later publisher-local calendar days, and “offline copy” states. These are context labels, not an invented legal expiry or guarantee that guidance is still valid. Live-page check failure and saved-source review remain separate. Unknown, well-shaped source references remain preserved and visibly unavailable by exact IDs; malformed records preserve existing work and fail validation rather than inventing a replacement. No current-source fallback silently upgrades an older reference.
4. Add optional `sourceRef` to existing action/draft inputs. Legacy absence stays absent. New publication accepts only a known exact snapshot; persisted well-shaped unknown references remain readable as unavailable. Do not validate rejected original payloads as published records: rejected operations/receipts must survive replay and restart. Copy the exact reference into create/change queues, successors and original history; do not relabel member plans as official.
5. “Start a community question” prepares the existing private composer only. Seed a genuinely blank or already-published draft; resume a draft for the same snapshot; preserve an unrelated unfinished draft and offer to open it instead. No silent merge or overwrite. The member supplies the question/context, reviews it and publishes through existing controls. An unknown reference can be removed deliberately from an unpublished draft without losing its text. Existing discussions for this exact opportunity/snapshot are discoverable from the source card; corrections remain member-provided and unverified.
6. Opening either external link changes no signup, attendance, application, registration, ballot, receipt or private progress. No automatic progress is added. All existing RSVP, claim, equal-weight ballot, lifecycle, minutes, identity and history behavior remains separate. The source city is NYC regardless of the viewer's selected city; no GPS or inferred personal eligibility.
